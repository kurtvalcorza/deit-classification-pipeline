# Weight and sample-data provenance and hosting

- Upstream: `facebook/deit-small-patch16-224`
- Revision: `164deee347853469b97442b3817f22eece80c7e3`, pinned 2026-09-25 by `python tools/pin_snapshot.py`, which resolved the Hub's `main` to this commit, downloaded every manifest-listed file at it, cross-checked each LFS file against the SHA-256 the Hub records, recorded the Hub's LFS SHA-256 of the reference file, and wrote the commit and digests into the manifest and `src/deit_classification_pipeline/pipeline.py`.
- Source checkpoint: `pytorch_model.bin` (88,283,631 bytes, SHA-256 `7eadf70de01e439569e1bbba8b5ef233b4bf70f25a98d9b33460095672bce38c`, also pinned in code as `SOURCE_WEIGHTS_SHA256`), a PyTorch pickle of the state dict. The Hub repository holds no SafeTensors file at the pinned revision, so the package converts this file locally and serves only the conversion.
- Served file: `model.converted.safetensors` (88,225,584 bytes, 200 tensors, SHA-256 `aad9d62d6a6a04e597ae664d33c95820ec26930f2b63bba0e1b935cff280f5be`, pinned as `CONVERTED_SHA256`). `convert_checkpoint` verifies the whole snapshot, reads `pytorch_model.bin` once with `torch.load(..., map_location="cpu", weights_only=True)` (which restricts unpickling to tensors and plain containers), requires a flat dict of tensors that strict-loads into the model built from `config.json`, clones every tensor into contiguous CPU storage and writes it with `safetensors.torch.save_file` and the one-key metadata `{"format": "pt"}`. A result with any other digest is deleted and refused. The conversion is byte-reproducible: two conversions on 2026-10-24 gave the same digest. Once it exists, `stage_missing_files` and `verify_snapshot` no longer require `pytorch_model.bin`.
- Equivalence (2026-10-24, CPU, torch 2.14.0, transformers 4.57.6): every converted tensor equals its source tensor, and on a deterministic 320×256 gradient image through DeiT's evaluation transform and on one seeded random 224×224 tensor, the model loaded from the conversion and the model loaded from `pytorch_model.bin` with `weights_only=True` returned identical logits (`torch.equal`, max abs difference 0.0). The converted key set equals the one transformers' `save_pretrained` writes, and the served model's state dict and logits equal those of `ViTForImageClassification.from_pretrained(<verified dir>, use_safetensors=False, weights_only=True)`.
- Hosted, not executed: `tf_model.h5` (88,505,432 bytes), the TensorFlow checkpoint. It is listed under `referenceFiles` in the manifest; the pin tool records its Hub LFS SHA-256 without downloading it, so the card can cite the digest of the hosted file and of the executed one.
- Manifest: `weights/deit-small-patch16-224/dimer-base-manifest.json` (4 staged files: `README.md`, `config.json`, `preprocessor_config.json`, `pytorch_model.bin`; `totalBytes` 88360671; plus the reference file). Every entry carries its SHA-256.
- Committed copy: `preprocessor_config.json` (160 bytes) is committed as the Hub serves it at the pinned commit, so a test can record that it differs from the transform the pipeline uses. The pin tool replaced it with the bytes downloaded at the pinned commit before hashing (they were byte-identical), so its digest describes the pinned bytes.
- Upstream weight license: Apache-2.0 (the checkpoint's `README.md` front matter). The model was trained on ImageNet-1k, whose images carry their own terms of access.
- Hosting: Apache-2.0 permits use, modification, distribution and commercial use, subject to keeping the licence and notices. The Git repository vendors neither the checkpoint nor its conversion (`weights/**/*.bin` and `weights/**/*.safetensors` are git-ignored).
- Fresh clone: `stage_missing_files(allow_download=True)` fetches only the manifest-listed files that are absent, at the pinned revision; `verify_snapshot()` then checks every file before any load. `weights/**` is marked `-text` in `.gitattributes`, so Windows `core.autocrlf` cannot rewrite the committed files and break their digests.
- Loader trust boundary: `ViTConfig.from_pretrained(<verified dir>, local_files_only=True)` and `ViTForImageClassification(config)` build the architecture without contacting the Hub or running repository code; `verify_converted` checks the conversion's digest and `load_state_dict(load_file(<conversion>), strict=True)` refuses a missing, unexpected or mis-shaped tensor; the serving path never calls `torch.load`; and the loader refuses a config whose labels at the zero-shot group indices are not the expected ImageNet classes.

## Tutorial sample data

- Dataset: `Cleanlab/cifar-10-subset`, file `CIFAR-10-subset.zip`, at commit `bb5a7aabf1d14d2d1e3e49d0d8f917bda3622f75`.
- Size and digest: 986,707 bytes, SHA-256 `66f90a4f87d865e8eb653b62f10e754684075a32314177de76832349d4b1fb19`. `fetch_sample_archive` refuses any other bytes and has no fallback.
- Licence: MIT (the dataset card). The images are CIFAR-10 images (Krizhevsky, 2009); the tutorial keeps the `frog` and `truck` folders.
- Hosting: the archive is downloaded at runtime into a working directory (`data/`, git-ignored) and is not redistributed by this repository.
